ScannerAz security overview

Last updated: September 25, 2026

ScannerAz is designed so Amazon authorization data remains on the backend and seller connections stay isolated. Production availability is contingent on completing the operational controls required for the selected Amazon access roles.

Application controls

  • HTTPS-only production access and security headers.
  • Short-lived, signed OAuth state values and HTTP-only authorization cookies.
  • Encrypted server-side storage for Amazon refresh tokens.
  • Request-size limits, rate limiting, and error responses that do not expose upstream credentials or provider responses.
  • Minimal-role access: Product Listing and Pricing only for the initial release.

Operational controls before public launch

DRECOM LLC will not enable public seller connections until the production environment has a private managed database, managed secret storage, web application firewall controls, monitoring and alerting, access reviews, and the documented incident-response process required by Amazon's policies.

Incident reporting

ScannerAz maintains an incident-response process with defined operational roles, containment steps, evidence preservation, periodic review, and an Amazon notification process for incidents involving Amazon Information.

Security questions

For security concerns, use the support channel and include only a high-level description. Do not include passwords, refresh tokens, API keys, or buyer information in a public message.
